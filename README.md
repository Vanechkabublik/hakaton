# Новости Vancodex — медиа с платной подпиской

Новостное издание с метрируемым пейволлом, подписками через ЮKassa, личным кабинетом, админкой и рассылками.
Чистый PHP 8.3 (собственный MVC без фреймворка, ООП), PostgreSQL 16, чистые HTML/CSS и JavaScript с AJAX.
Разворачивается одной командой в Docker, HTTPS-сертификат Let's Encrypt выпускается автоматически.

- **Сайт:** https://news.vancodex.tech
- **Админка:** https://news.vancodex.tech/admin

## Быстрый старт на сервере

Нужен сервер с Linux (Ubuntu/Debian), 1 ГБ ОЗУ и выше, **свободные порты 80 и 443**.

1. **DNS.** Создайте A-запись `news.vancodex.tech` → IP сервера (и AAAA, если есть IPv6).
   Сертификат не выпустится, пока домен не указывает на сервер.
2. **Код на сервере:**
   ```bash
   git clone https://github.com/Vanechkabublik/hakaton.git /opt/news && cd /opt/news
   ```
3. **Деплой** (на чистом сервере без Docker добавьте `--install-docker`, нужен root):
   ```bash
   sudo ./deploy.sh --install-docker
   ```
   Скрипт спросит домен и email для Let's Encrypt, сам создаст `.env` со случайными `APP_KEY`, паролем БД и
   паролем администратора, соберёт образы, поднимет стек, применит миграции, создаст рубрики/тарифы/страницы и
   дождётся выпуска сертификата. В конце выведет логин и пароль администратора.

   Без вопросов: `DOMAIN=news.vancodex.tech ACME_EMAIL=you@example.com ADMIN_EMAIL=you@example.com ./deploy.sh`

4. Откройте https://news.vancodex.tech/admin, войдите, **включите 2FA** (для админов и редакторов обязательна)
   и смените пароль. Дальше — [настройка интеграций](#настройка-интеграций).

Повторный запуск `./deploy.sh` — это и есть обновление: `git pull`, пересборка образов, перезапуск с новой версией,
применение новых миграций. Данные (БД, загрузки, сертификаты) лежат в Docker-томах и не затрагиваются.

| Параметр `deploy.sh` | Что делает |
|---|---|
| `--no-pull` | не делать `git pull` (деплой текущего состояния каталога) |
| `--staging` | тестовый центр сертификации Let's Encrypt — для проб, без лимитов (браузеры ему не доверяют) |
| `--production` | вернуться на боевой Let's Encrypt |
| `--install-docker` | установить Docker, если его нет |

### Из чего состоит стек (`docker-compose.yml`)

| Сервис | Образ | Назначение |
|---|---|---|
| `caddy` | `caddy:2-alpine` | единственная точка входа: HTTPS (Let's Encrypt, автопродление), редирект HTTP→HTTPS, HTTP/3, сжатие, статика, кэш |
| `app` | собственный (`php:8.3-fpm-alpine`) | php-fpm; при старте применяет миграции и начальные данные |
| `worker` | тот же образ | очередь писем/push/рассылок и планировщик (публикация по расписанию, автопродление, дайджесты, бэкапы) |
| `db` | `postgres:16-alpine` | база данных, наружу порт не публикуется |

Тома: `pgdata` (БД), `uploads` (загрузки редакции), `backups` (ночные дампы), `logs`, `caddy_data` (сертификаты — не удаляйте,
иначе придётся выпускать заново и можно упереться в лимиты Let's Encrypt).

## Настройка интеграций

Всё вводится в админке: **Настройки** (значения из админки приоритетнее переменных окружения). Секреты хранятся
в БД зашифрованными (libsodium, ключ — `APP_KEY`) и в формах никогда не показываются.

### ЮKassa

Тестовый магазин уже создан — используйте его ключи, затем замените на боевые.

1. В личном кабинете ЮKassa: **Интеграция → Ключи API** — скопируйте `shopId` и создайте секретный ключ.
2. Админка → **Настройки → ЮKassa**: введите `shopId` и секретный ключ, сохраните. Кнопка **«Проверить подключение»**
   обратится к API и покажет данные магазина.
3. В кабинете ЮKassa: **Интеграция → HTTP-уведомления** — URL `https://news.vancodex.tech/webhooks/yookassa`,
   события: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
   Тело уведомления не считается доверенным: сервер заново запрашивает платёж через API, поэтому подделать оплату нельзя.
4. Автопродление: включите в кабинете ЮKassa **«Автоплатежи»** (сохранение способа оплаты). Без этого карта не сохраняется;
   сайт при отказе сам продолжит работу без автопродления. Отключить рекуррентные платежи можно в *Настройки → Подписки и платежи*.
5. Чеки 54-ФЗ: если подключены «Чеки от ЮKassa», оставьте включённым «Передавать данные чека» и выберите ставку НДС и
   систему налогообложения. Заполните юрлицо/ИП и ИНН (*Настройки → Сайт*) — они попадают на квитанции.
6. Способ оплаты: редирект на страницу ЮKassa либо встроенный виджет (*Настройки → ЮKassa → Способ оплаты*).

Тестовые карты ЮKassa: `5555 5555 5555 4444` (успех), срок — любой будущий, CVC — любой.
Сверка зависших платежей идёт автоматически каждые 15 минут и вручную: `make console ARGS="payments:reconcile"`.

### Яндекс ID (вход и привязка аккаунта)

1. https://oauth.yandex.ru → создать приложение, платформа «Веб-сервисы».
2. **Redirect URI:** `https://news.vancodex.tech/auth/yandex/callback`.
3. Права: `login:email`, `login:info`, `login:avatar`.
4. Админка → **Настройки → Яндекс ID (OAuth)**: Client ID и Client secret.

Пользователи могут привязать/отвязать Яндекс ID в кабинете (отвязать можно, только если у аккаунта задан пароль).

### Почта (SMTP)

Письма (подтверждение email, сброс пароля, чеки, напоминания, дайджесты, рассылки) уходят через очередь.
*Настройки → Почта (SMTP)*: сервер, порт, шифрование, логин/пароль, адрес отправителя; кнопка **«Отправить тестовое письмо»** (придёт на email администратора).
Для доставляемости настройте у домена SPF, DKIM и DMARC у вашего почтового провайдера.
Пока SMTP не настроен, в production письма **не доставляются** — подтверждение email работать не будет.

### Web Push

```bash
make console ARGS="vapid:generate"
```
Вставьте ключи в *Настройки → Push-уведомления*. Service Worker и подписка на уведомления подключатся автоматически.

### Аналитика

*Настройки → Аналитика*: номер счётчика Яндекс.Метрики и/или Measurement ID Google Analytics 4. Скрипты подключаются
только после согласия пользователя в cookie-баннере. Внутренняя аналитика (просмотры, источники, дочитываемость,
воронка пейволла) работает всегда и не зависит от внешних счётчиков.

### Тексты и юридические страницы

Страницы «О проекте», «Контакты», «Реклама», «Правила комментариев», «Пользовательское соглашение», «Политика
конфиденциальности» создаются при установке **шаблонными текстами** и редактируются в *Админка → Страницы*.
**Обязательно проверьте их с юристом** и подставьте реквизиты (юрлицо/ИП, ИНН, контакты) — это ваша ответственность.

## Эксплуатация

Основные команды (`make help` — полный список):

```bash
make ps                        # состояние сервисов
make logs                      # логи всех сервисов
make console ARGS="migrate"    # консольная команда приложения
make psql                      # консоль PostgreSQL
make backup                    # дамп БД (сохраняется в ./backups и в том backups)
make restore FILE=backups/db-20261019-030000.sql.gz
```

| Задача | Команда |
|---|---|
| Обновить сайт | `./deploy.sh` |
| Создать администратора/редактора | `make console ARGS="user:create-admin me@example.com --name='Имя' --role=editor"` |
| Сбросить 2FA (потерян телефон и коды) | `make console ARGS="user:reset-2fa me@example.com"` |
| Сгенерировать ключ приложения | `make console ARGS="key:generate"` |
| Демо-материалы (только для показа) | `make console ARGS="demo:seed"` |
| Применить задачи планировщика сейчас | `make console ARGS="schedule:run"` |

**Бэкапы.** Каждую ночь в 03:30 воркер делает дамп БД (хранятся 7 последних, том `backups`). Также дамп можно скачать
в админке (*Безопасность → База данных*). Копируйте дампы за пределы сервера (cron + rsync/rclone/S3) — резервная копия
на том же диске не защитит от потери сервера. Каталог загрузок: том `uploads`
(`docker run --rm -v news_uploads:/data -v $PWD:/out alpine tar czf /out/uploads.tgz -C /data .`).

**Ключ `APP_KEY`.** Храните отдельно от сервера. Без него нельзя расшифровать сохранённые секреты (ключи ЮKassa, SMTP,
Яндекс) — их придётся ввести заново; сессии и подписанные ссылки тоже станут недействительны.

**Аудит и логи.** Все значимые действия (входы, выдача подписок, возвраты, правки настроек) пишутся в журнал аудита
(*Безопасность → Журнал действий*). Логи приложения: `docker compose logs app worker`, access-логи Caddy: `docker compose logs caddy`.

**Если сертификат не выпускается:** проверьте DNS (`dig +short news.vancodex.tech`), открытые порты 80/443 (в т.ч. в
файрволе облачного провайдера) и `docker compose logs caddy`. Для отладки используйте `./deploy.sh --staging`.
Если домен за Cloudflare — включите режим DNS only на время выпуска или используйте DNS-challenge.

## Локальная разработка и тесты

Через Docker (сайт на https://localhost с локальным сертификатом Caddy):

```bash
cp .env.example .env
# DOMAIN=localhost, APP_URL=https://localhost, ACME_EMAIL=dev@example.com, DB_PASSWORD=dev,
# APP_ENV=local, APP_DEBUG=1, ADMIN_EMAIL=admin@example.test, ADMIN_PASSWORD=Admin12345a
docker compose up -d --build
make console ARGS="demo:seed"
```

Без Docker: PHP 8.3 (расширения `pdo_pgsql gd intl sodium mbstring curl dom`), PostgreSQL 16, `composer install`,
`.env` с `DB_HOST=127.0.0.1`, затем:

```bash
php bin/console migrate && php bin/console seed && php bin/console demo:seed
php -S 127.0.0.1:8080 -t public public/index.php
php bin/console worker          # в отдельном терминале: письма, очередь, планировщик
```

**Тесты** — PHPUnit, 312 тестов: юнит (TOTP по векторам RFC 6238, санитайзер HTML, деньги, периоды, роутер, DI,
валидатор, расписание) и интеграционные на настоящей PostgreSQL (авторизация и 2FA, пейволл, биллинг с фейковым
шлюзом ЮKassa: вебхуки, повторы, подмена суммы, продление, возвраты, промокоды, подарки; редакционный процесс,
комментарии, SEO, очередь, планировщик, лимиты, шифрование настроек).

```bash
createdb news_test                  # база для тестов; имя ОБЯЗАНО оканчиваться на _test
DB_USER=... DB_PASSWORD=... vendor/bin/phpunit
```

Интеграционные тесты **пересоздают схему** базы `*_test` (на другие базы они откажутся запускаться).
CI (`.github/workflows/ci.yml`) гоняет линтер, тесты на PostgreSQL, проверку `docker compose config`, валидацию
`Caddyfile` и сборку образа.

## Архитектура

```
public/index.php          единственная точка входа (фронт-контроллер)
src/Core/                 ядро: DI-контейнер с автовайрингом, роутер, HTTP, шаблонизатор, БД (PDO),
                          сессии в БД, CSRF, rate limiting, шифрование, очередь, планировщик, почта, консоль
src/<Домен>/              Article, Auth, Billing (+Gateway), Comment, Engagement, Media, Newsletter, Notification,
                          Paywall, Analytics, Seo, Settings, Taxonomy, User, Page, Audit, Schedule, Seed
src/Http/                 контроллеры (Web, Account, Billing, Admin), middleware, ViewComposer
templates/                PHP-шаблоны (layouts, partials, web, admin, mail)
migrations/               SQL-миграции (применяются по порядку, под advisory lock)
public/assets/            чистые CSS и JS (без сборщиков и фреймворков), public/sw.js — Service Worker
docker/, Dockerfile       образ приложения, конфиги PHP и Caddy
```

Принципы: каждая сущность — класс (`Article`, `Subscription`, `Payment`…) со своим репозиторием и сервисом;
деньги — целые числа в копейках; внешние системы за интерфейсами (`PaymentGateway`, `Transport`) — их подменяют в тестах;
время жизни процесса не используется для состояния (всё в БД), поэтому php-fpm и воркеры масштабируются горизонтально.

Данные: PostgreSQL 16 — полнотекстовый поиск на русской морфологии (`tsvector`, `ts_headline`) + `pg_trgm` для
автодополнения, `FOR UPDATE SKIP LOCKED` для очереди, keyset-пагинация ленты, незалогируемая таблица для rate limit.

## Возможности

**Публичная часть.** Лента с AJAX-подгрузкой (курсор) и фильтрами по рубрикам/тегам/типам; поиск с автодополнением
и подсветкой; страница статьи с прогресс-чтением, временем чтения, шерингом, «Сохранить», «Читайте также», живыми
хрониками (live-блог), галереями; комментарии деревом с лайками, жалобами, правкой в течение 5 минут и
премодерацией ссылок; реакции; тёмная тема; RSS и RSS по рубрикам, `sitemap.xml`, `robots.txt`, PWA-манифест;
cookie-баннер с категориями согласий.

**Пейволл.** Три уровня доступа (бесплатно / Digital / Premium). Для Digital — метрируемый бесплатный лимит статей
в месяц (по cookie-посетителю и по аккаунту вместе), Premium закрыт сразу. Поисковые боты и соцсети получают
превью (с разметкой `isAccessibleForFree` для Google), в HTML закрытая часть не попадает. Тексты блока и лимит
настраиваются в админке; воронка «показ → клик → покупка» считается на дашборде.

**Регистрация и вход.** Email + подтверждение, вход, «запомнить меня» (ротируемый токен), восстановление пароля,
Яндекс ID (вход, привязка/отвязка), TOTP 2FA с кодами восстановления (обязательна для админов и редакторов),
защита от перебора (лимиты по аккаунту и IP), защита от фиксации сессии, список активных сессий с выходом.

**Личный кабинет.** Профиль, подписка (смена тарифа, отмена автопродления, отвязка карты), история платежей с
квитанциями, закладки, история чтения, свои комментарии, уведомления, подписки на авторов, удаление аккаунта.

**Подписки и оплата.** Тарифы месяц/год × Digital/Premium, редирект или виджет ЮKassa, вебхуки, автопродление по
сохранённой карте с повторами и льготным периодом, апгрейд с пропорциональным зачётом остатка, отложенный даунгрейд,
полные и частичные возвраты, промокоды (процент/сумма, лимиты, сроки, привязка к тарифам, «только первый платёж»),
пробный период без карты, подарочные подписки по коду, напоминания об окончании.

**Контент.** Шесть типов (новость, аналитика, лонгрид, мнение, фоторепортаж, live-блог), статусы
«черновик → модерация → опубликовано → архив», отложенная публикация, предпросмотр по подписанной ссылке,
история правок с откатом, редактор с очисткой вставляемого HTML, медиатека с автоматическим ресайзом в WebP
(5 размеров), рубрики и теги, связанные материалы вручную и по тегам.

**Админка.** Дашборд (выручка, MRR, активные подписки, конверсия пейволла, новые пользователи, топ статей, источники
трафика, графики), контент и модерация, комментарии, пользователи (поиск, фильтры, выдача/отзыв подписки, блокировка,
роли, экспорт CSV, история), платежи (список, возвраты, сверка, экспорт, журнал вебхуков), подписки/тарифы/промокоды,
настройки (название, логотип, SEO-шаблоны, SMTP, ключи, тексты пейволла), рассылки (кампании, сегменты, очередь),
безопасность (аудит, экспорт БД, управление 2FA сотрудников).

**Уведомления и удержание.** Ежедневный/еженедельный дайджест, ответы на комментарии, новые материалы любимых авторов,
Web Push, онбординг-серия после регистрации, письма о платежах/неудачном списании/окончании подписки; отписка в один клик.

**SEO.** ЧПУ, `title`/`description` по шаблонам, canonical, Open Graph, Twitter Cards, JSON-LD (`NewsArticle`,
`BreadcrumbList`), sitemap, RSS, robots.

## Безопасность

- **CSRF** на всех небезопасных запросах (токен в форме или заголовке `X-CSRF-Token`), исключены только вебхуки и счётчики.
- **SQL-инъекции:** только параметризованные запросы PDO; динамические фрагменты строятся из белых списков.
- **XSS:** экранирование по умолчанию во всех шаблонах; HTML статей и комментариев чистится серверным санитайзером
  (белый список тегов/атрибутов, схемы URL, `rel=noopener`, sandbox для встраиваний); строгий **CSP с nonce**
  для скриптов; загрузки отдаются с `sandbox` в CSP.
- **Пароли** — Argon2id; проверка постоянного времени для несуществующих аккаунтов; одинаковые ответы при входе и
  восстановлении (нельзя узнать, зарегистрирован ли email).
- **Сессии** в БД, идентификатор хранится хешем, ротация при входе, `HttpOnly`, `Secure`, `SameSite`.
- **2FA TOTP** (RFC 6238), одноразовые коды восстановления, защита от повторного использования кода.
- **Rate limiting** на вход, регистрацию, сброс пароля, комментарии, оплату, поиск и др.
- **Платежи:** идемпотентные запросы, перепроверка уведомлений через API, сверка сумм, шифрование ключей.
- **Заголовки:** HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `frame-ancestors`.
- **Журнал аудита** действий сотрудников и критичных событий.

## Ограничения и что проверить перед запуском

Проверено автотестами и вживую на PostgreSQL (регистрация и вход, 2FA, пейволл, оплата через фейковый шлюз, админка,
загрузка медиа, визуально — светлая/тёмная темы и мобильная версия). **Не проверялось на настоящих внешних сервисах**
(в среде разработки они недоступны), поэтому после первого деплоя пройдите чек-лист:

- [ ] Сертификат выдан, https://news.vancodex.tech открывается, HTTP редиректит на HTTPS.
- [ ] Вход админа, включение 2FA, смена пароля.
- [ ] *Настройки → Почта (SMTP)* → тестовое письмо дошло (не в спаме); регистрация нового читателя и подтверждение email.
- [ ] *Настройки → ЮKassa* → «Проверить подключение»; вебхук указан в кабинете ЮKassa.
- [ ] Тестовая оплата тарифа в тестовом магазине: подписка появилась, письмо с чеком пришло, в *Платежи* статус «Оплачен».
- [ ] Возврат из админки (тестовый платёж) закрывает доступ; автопродление: в кабинете ЮKassa включены «Автоплатежи».
- [ ] Яндекс ID: вход и привязка из кабинета (Redirect URI совпадает).
- [ ] Юридические страницы вычитаны юристом, реквизиты и контакты подставлены.
- [ ] Настроено копирование бэкапов за пределы сервера.

Известные ограничения: пробный период выдаётся без привязки карты (поэтому автоматически в платный не переходит —
читатель оформляет подписку сам); анимация GIF при ресайзе не сохраняется; квитанция в кабинете — нефискальная
(фискальный чек присылает ЮKassa); для `pg_dump` в образе используется клиент PostgreSQL из Alpine (совместим с 16).
